报告涉及三种方案。lead 可以自己研究，也可以把独立资料调查交给子 agent。**当独立并行、专业能力或上下文隔离能带来收益时，委派才值得付出协调成本。** 三个子任务若要修改同一份报告，协调成本和冲突可能抵消并行收益。

子 agent 是另一个完整 agent，不是某个 middleware 中的一次模型调用。lead 的工具节点调用 `task`，工具再启动 executor，executor 装配并运行子图。

## task 工具是调度适配层

<SourceRef file="backend/packages/harness/deerflow/tools/builtins/task_tool.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="task_tool" /> 接受任务 prompt、subagent type、描述，可选的 `context_mode`、模型与 `acceptance_criteria`。它准备父级上下文，执行准入与调度，观察子任务，最后返回可供 lead 消费的结果。

正常结果路径通过 Command 写入 ToolMessage，将子任务的结果、状态、用量和验收信息一起交回 lead。

<SourceRef file="backend/packages/harness/deerflow/subagents/executor.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentExecutor" /> 则负责创建子 graph、执行循环、超时、取消及结果采集。provider 的 `tool_call_id` 用于消息与 UI 关联；服务端生成的 `execution_id` 用于 registry、取消和所有权。不同 run 的 provider ID 可能重复，不能作为全局执行主键。

## 继承足够的现场，收窄执行能力

| 维度 | 当前行为 |
| --- | --- |
| 用户、thread、workspace | 延续父级身份和共享执行现场 |
| 模型 | 可继承或按配置选择，受授权与显式选择约束 |
| 工具 | 根据子 agent 配置与执行授权收窄，避免递归 task |
| Skills | 限制发现与激活；allowed-tools 是元数据，不参与工具授权 |
| 对话上下文 | `isolated` 与有界 `snapshot` 是不同模式 |
| checkpoint | 普通子 graph 使用 `checkpointer=False`，不是可独立 resume 的长期会话 |
| 资源 | 共享 sandbox，但持有自己的 execution lease |

<SourceRef file="backend/packages/harness/deerflow/subagents/context_snapshot.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 提供有界父上下文快照；它不是把父 graph 的所有内部状态与权限复制给子 agent。子 agent 的 skill 发现范围也不能用来重写 lead 拥有的共享文件视图。

## 有三种不同的预算

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/subagent_limit_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentLimitMiddleware" /> 处理模型提出的委派数量；<SourceRef file="backend/packages/harness/deerflow/subagents/capacity.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 管理进程执行容量；<SourceRef file="backend/packages/harness/deerflow/subagents/config.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentConfig" /> 与 <SourceRef file="backend/packages/harness/deerflow/subagents/turn_budget.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 管理子执行的 turns 和时间上限。

- 每轮并发限制：这次模型返回可以放行几个 task。
- 每 run 总量限制：不能通过多轮不断发新 task 绕开预算。
- 子执行 turn/time 限制：一个已启动的子 agent 能运行多久。

`max_turns` 表示 agent 轮次，需要按装配后的图结构换算成 LangGraph 的 super-step（图整体推进一步）预算。并发、总量、轮次与超时各有配置，阅读时应跟踪本次运行的有效值。

## completed 不等于验收通过

子 agent 返回的“我完成了”是自述。当前结果还可以携带 receipts 与确定性验收：

| 验收条件示例 | 可以检查 | 不能据此推出 |
| --- | --- | --- |
| 文件 exists / non-empty | 文件存在或有内容 | 内容正确、来源充分 |
| `file_written` | 当前执行有匹配写入证据 | 最终内容满足业务需求 |
| `tests_passed` | 与已记录命令及测试输出对应 | 所有测试与所有环境通过 |
| JSON / CSV 条件 | 支持范围内的语法或表头 | 完整 schema 与业务语义正确 |
| 自由文本要求 | 未必可确定性检查 | 不能自动判为通过 |

<SourceRef file="backend/packages/harness/deerflow/subagents/acceptance_checks.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 对无法判定或证据不足的条件保留 `UNVERIFIED`。已完成执行、条件不满足和缺少证据是三种不同结果；lead 应复用已经成立的产物，只补足未满足的条件。

对于报告，文件存在可以自动验证，但三种方案的比较是否公允、来源是否支持结论，仍需检查实际材料。

## 普通 task 与持久化 batch 不同

<SourceRef file="backend/packages/harness/deerflow/tools/builtins/batch_task_tool.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 提供 `batch_task`、`batch_status`、`cancel_batch` 和 `read_batch_result`。<SourceRef file="backend/packages/harness/deerflow/subagents/batch_service.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentBatchService" /> 对 batch item 做持久化调度、租约与恢复，适合有界、独立的批量工作。

批任务持久化保存 item 状态与结果，并据此协调恢复；普通子 graph 使用 `checkpointer=False`。启用批任务需要持久化数据库及对应服务配置。

<Philosophy>
委派把计算分开，也把证据分开。父 agent 综合报告时，需要知道谁执行了什么、为何停止、哪些条件已被证实、哪些仍需核实。
</Philosophy>
