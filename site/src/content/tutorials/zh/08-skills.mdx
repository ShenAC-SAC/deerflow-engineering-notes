生成带来源的报告，可以用一个 skill 约定资料筛选、引用格式和产物检查方法。它把工作流程、参考资料与脚本放进包里，模型需要时读取。

**skill 将工作方法组织成可复用的包；它能使用哪些能力，由 agent 配置、授权和运行策略决定。**

## 包、元数据与存储范围

<SourceRef file="backend/packages/harness/deerflow/skills/types.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="Skill" /> 记录名称、描述、目录、分类、启用状态、兼容字段和 secret 声明。<SourceRef file="backend/packages/harness/deerflow/skills/parser.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 解析 frontmatter（SKILL.md 开头用 `---` 包起来的元数据）并发现技能包；`SKILL.md` 所在目录是包边界，不能把每个深层同名文件都当成独立顶级技能。

public 技能是共享来源；custom 技能需要明确用户归属。<SourceRef file="backend/packages/harness/deerflow/skills/storage/user_scoped_skill_storage.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="UserScopedSkillStorage" /> 将用户的 custom 内容放进其自己的范围，同时保留共享 public 读取。集成技能通过对应的注册与投影机制加入运行时，共同构成可发现的技能来源。

以一个假设的报告技能为例，包内可以包含：

~~~text
report-sources/
  SKILL.md
  references/citation-guide.md
  scripts/check_links.py
~~~

`SKILL.md` 描述流程，references 提供资料，scripts 放置辅助程序；脚本执行取决于实际工具、环境与授权。

## 两种发现模式，一个按需加载原则

未启用 `skills.deferred_discovery` 时，prompt 列出技能元数据；启用后，prompt 使用紧凑的 skill index，并通过 <SourceRef file="backend/packages/harness/deerflow/skills/describe.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="build_describe_skill_tool" /> 构建的工具按需获取元数据。

`describe_skill` 返回说明和路径，模型据此决定是否读取完整 SKILL.md。它负责技能发现；MCP 的 `tool_search` 负责工具 schema 晋升，两者使用独立开关。

用户显式以 `/skill` 激活时，<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/skill_activation_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SkillActivationMiddleware" /> 提供确定性的正文加载路径。显式选择仍受可用范围与激活授权检查，不能仅凭一个名字越过权限。

## 可见、可激活、可执行是三回事

| 边界 | 负责机制 |
| --- | --- |
| 能否出现在候选 skill 列表 | agent 范围与资源授权 |
| 能否 describe 或显式激活 | `skill:activate` 等动作授权 |
| 能否在 sandbox 读取实际文件 | provider 支持与 managed projection |
| 能否运行某个工具调用 | agent 工具配置、工具授权和运行策略 |

<SourceRef file="backend/packages/harness/deerflow/authz/skill_filter.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 处理 skill 授权。自定义 provider 可以允许资源可见却拒绝激活，因此“出现在列表”不等于“允许执行流程”。

parser 与 Skill 保存 `allowed-tools`，用于兼容和元数据交换。这个字段的取值与 skill 激活都不改变 agent 的工具权限范围。

## 文件投影决定实际可见范围

<SourceRef file="backend/packages/harness/deerflow/skills/projection.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 根据 enabled 状态和 agent 范围建立 managed view，提供给 `/mnt/skills`。受限 thread 的视图使用副本隔离，检查包路径和链接，并维护稳定挂载根与更新签名。

复制与内容签名会增加 I/O 和存储开销，换来视图与技能源文件之间的写入隔离：sandbox 修改副本时，源文件保持独立。切换策略时也要撤销旧范围，不能只追加新技能。

这不是所有 provider 都天然支持的保证。不能实施物理技能隔离的 provider 必须明确处理受限配置；子 agent 也不能重建 lead 拥有的共享投影。

## 从安装到发布有一道关口

<SourceRef file="backend/packages/harness/deerflow/skills/installer.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="safe_extract_skill_archive" /> 无条件约束归档路径、成员数量、解压大小和可执行二进制等风险。扫描配置启用后，原生 <SourceRef file="backend/packages/harness/deerflow/skills/skillscan/orchestrator.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 和内容安全扫描再检查包内文本及脚本，然后才发布到目标存储。

扫描通过只能说明检查器没有拦截该内容，不能证明脚本运行安全或内容不会误导模型。静态扫描、模型审查、工具授权和执行隔离各自解决不同问题。

对于 `skill_manage`，<SourceRef file="backend/packages/harness/deerflow/tools/skill_manage_tool.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 将 agent 写入约束在受管技能操作里。扩展宿主还提供 <SourceRef file="backend/packages/harness/deerflow/skills/mutations/service.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="HostSkillMutationService" />：stage、check、revision 检查和发布有明确流程，不能把“生成了建议正文”当作“已经更新生产 skill”。

## Secret 在执行期绑定

Skill 可以声明 required secrets；是否绑定还与激活方式和策略有关。secret 值应留在执行期能力通道，不进入 SKILL.md、对话、checkpoint 或可分享产物。技能描述可解释需要哪种凭据，但不能通过文字请求替自己获取更多权限。

<Philosophy>
渐进加载让大量技能不会一次占满上下文；资源授权与物理投影则决定哪些技能真能被看见。把这两件事分开，既能优化发现，也不必把“没写进 prompt”误当成访问控制。
</Philosophy>
