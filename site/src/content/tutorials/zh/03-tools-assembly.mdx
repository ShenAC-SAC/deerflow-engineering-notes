为了比较方案，agent 可能需要读取文件、搜索资料、委派研究，最后写出报告。这些能力要经过装配与授权。**工具系统分别决定：有哪些候选工具、本轮暴露哪些 schema、这次调用是否允许执行。**

## 候选工具从哪里来

<SourceRef file="backend/packages/harness/deerflow/tools/tools.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="get_available_tools" /> 从应用配置、内置工具和接入系统构造候选集。配置工具使用 `module.path:variable_name` 导入对象；agent 的 `tool_groups`、模型视觉能力、host bash policy 和宿主能力决定哪些能进入候选集。

配置中的 `name` 是配置标签，`BaseTool.name` 才是模型 schema 与运行时路由使用的名称。最后的去重也按工具实际名称进行，因此同名工具的来源与先后顺序会影响结果。

MCP 和 ACP 提供外部能力；extension 工具也要通过宿主的装配与策略，不应被理解成额外的免检入口。

## 授权覆盖所有工具来源

工厂还会补充 `describe_skill`、memory、项目文档等工具。这些晚加入的候选也进入 <SourceRef file="backend/packages/harness/deerflow/authz/tool_filter.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="apply_tool_authorization" />，避免“主列表检查了，追加工具却漏掉了”。

middleware 同样可能声明工具，例如任务清单。<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/tool_declarations.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="narrow_declared_tools" /> 与后续校验将这些声明纳入同一个权限边界。只检查传给 `create_agent(tools=...)` 的参数是不够的。

运行时另通过 <SourceRef file="backend/packages/harness/deerflow/guardrails/middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="GuardrailMiddleware" /> 执行调用检查。装配期回答“是否提供这个工具”，执行期回答“这次调用是否允许”。拒绝调用必须形成可理解的工具结果，不能假装工具已经执行。

## Skill 元数据与工具授权

`SKILL.md` 的 `allowed-tools` 是兼容元数据，不参与 agent 工具列表过滤或执行授权。

<SourceRef file="backend/packages/harness/deerflow/skills/types.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="Skill" /> 保存这个字段。实际工具权限由 agent 配置、授权 provider 和运行时策略决定；skill 的可见性与激活权限由资源授权链管理。

判断本次 run 能使用哪些工具，应检查装配结果与执行策略；`allowed-tools` 的取值不改变这一权限范围。

## Deferred：有工具，不一定先给 schema

当 `tool_search.enabled` 开启时，<SourceRef file="backend/packages/harness/deerflow/tools/builtins/tool_search.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="assemble_deferred_tools" /> 将 MCP 工具放入目录，模型先获得较小的发现入口，再通过 `tool_search` 晋升需要的 schema。

~~~text
注册与授权
  → deferred catalog + catalog_hash
  → tool_search 查找工具
  → 更新 promoted 状态
  → 后续模型调用暴露对应 schema
  → 执行时继续检查晋升与授权
~~~

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/deferred_tool_filter_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="DeferredToolFilterMiddleware" /> 同时管理模型可见性和未晋升调用的拦截。`promoted` 受 catalog hash 约束；目录变化后，旧的同名晋升不能直接变成新工具的权限。

配置还可以启用 MCP routing 自动晋升。它是 schema 发现的辅助路径，不会绕过授权。Skills 自己的 `skills.deferred_discovery` 是独立开关，第八站再展开。

## 工具返回值如何影响执行

| 工具类型 | 例子 | 返回后的影响 |
| --- | --- | --- |
| 读取或执行 | 文件读取、搜索、shell | 得到供下一轮模型消费的结果，也可能产生外部副作用 |
| 状态更新 | `present_files` | 通过 Command 更新产物状态，供界面展示 |
| 控制流 | `ask_clarification` | 由 middleware 改变 run 的继续方式 |
| 委派 | `task` | 启动子 agent，回传结果与关联证据 |
| 能力发现 | `tool_search`、`describe_skill` | 改变后续可见信息；不代表取得更高权限 |

模型可能先调用 `read_file`，发现资料不足，再请求搜索；也可能先澄清“比较哪三种方案”。这个分支取决于输入和运行策略，不由工具注册顺序预先安排。

## MCP 还有会话与文件边界

<SourceRef file="backend/packages/harness/deerflow/mcp/tools.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> 不只获取 schema，还包装会话、调用和返回内容。stdio session 的作用域、workspace、临时文件与虚拟路径映射，决定外部工具生成的文件能否回到当前 thread。

“能调用 Playwright MCP”和“截图能被当前用户下载”是不同问题。前者涉及工具与连接，后者还涉及路径、产物元数据、属主和持久化。MCP 的长任务机制也不能简单等同于一个永远阻塞的 tool call。
