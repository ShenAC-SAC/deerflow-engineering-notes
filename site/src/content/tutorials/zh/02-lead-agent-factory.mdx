工厂向 Gateway 返回 `LeadAgentAssembly`，其中包含可执行图、最终模型和按需生成的装配描述。

## 先决定身份，再收窄能力

内部核心先解析有效用户身份，再读取该用户的自定义 agent 配置。客户端普通字段不能覆盖宿主认证保留字段。随后计算：

- agent skills 与资源授权的交集；
- 允许的子 agent 类型、并发和总量；
- 是否允许交互式澄清、宿主是否提供调度能力；
- 模型选择与工具授权。

例如 `allowed_subagents=[]` 禁止委派，客户端的 `subagent_enabled=true` 无法将它重新打开。调度能力由宿主在运行时提供，checkpoint 中的配置字段不能授予这项权限。

## 模型选择包括能力归一化

常规选择从请求、agent 默认和全局配置解析模型，再应用授权。如果用户显式指定了模型，还要校验 `model_selection_requested` 与解析出的 `model_name` 一致、且该模型已配置；不满足就直接报错，而不是悄悄换成另一个模型。

`thinking_enabled` 等选项区分“未传”与“显式 false”。<SourceRef file="backend/packages/harness/deerflow/models/reasoning.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="resolve_reasoning_request" /> 再按模型的 reasoning contract 处理：关闭不支持的 thinking、开启必需的 thinking，或将 effort 映射成 provider 的词汇。

因此，用户请求的设置与最终采用的设置可能不同。运行 metadata 和 `effective_model` 要描述实际执行情况。

<MarginNote>图内模型创建使用 `attach_tracing=False`，因为 tracing callback 在图调用根部绑定。重复绑定可能产生重复 span 并破坏用户、会话归因。</MarginNote>

## 一次执行的装配步骤

常规分支依次完成：

1. 获取候选工具，追加 skill discovery、memory、项目文档和任务连续性等本次可用工具。
2. 应用工具授权，再构建 MCP deferred catalog。
3. 组合 middleware 与 extensions，收窄并校验 middleware 声明的工具。
4. 用同一组有效能力构造 prompt，避免提示词承诺不存在的工具。
5. 选择 checkpoint 兼容的状态 schema，调用 `create_agent()`。
6. 返回 `LeadAgentAssembly`。

`bootstrap` 是用于创建自定义 agent 的窄能力分支。某些 webhook 来源也会禁用 agent 自修改工具，避免外部评论获得持久修改 agent 的能力。

## 为什么状态 schema 参与装配

<SourceRef file="backend/packages/harness/deerflow/runtime/checkpoint_mode.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="freeze_checkpoint_channel_mode" /> 将 `full` 或 `delta` 固定为进程级选择。<SourceRef file="backend/packages/harness/deerflow/agents/thread_state.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="get_thread_state_schema" /> 提供相应结构，middleware 状态 schema 也要保持一致。

这不是随每个 prompt 切换的偏好。共享 checkpoint 数据库的进程必须兼容；改变模式需要重启，已有数据仍须经过兼容性检查。

## 装配描述记录什么

`LeadAgentAssembly` 有三个核心字段：

| 字段 | 意义 |
| --- | --- |
| `graph` | 实际执行的图 |
| `effective_model` | 最终使用的模型 |
| `descriptor` | 按需生成的装配描述；没有对应证据消费者时可以为 None |

描述符记录模型、工具、middleware 与有效策略，供扩展和审计使用。它描述执行配置，不承担任务结果的正确性验证，也不能替代可执行图。

<Philosophy>
将 graph 与装配依据一起返回，使执行对象与解释它的数据共享边界。兼容宿主只取 graph，需要证据的宿主保留描述；各自的需求不必靠给 graph 随意挂属性实现。
</Philosophy>
