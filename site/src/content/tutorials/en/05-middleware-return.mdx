The model may propose searches and a report write, or ask for the comparison scope. Tool calls require checks before execution. **Middleware decides which calls execute, how results are recorded, and when to stop.**

Three boundaries differ: `after_model` processes responses; `wrap_tool_call` surrounds tools; `after_agent` handles normal graph completion. The worker must also handle exceptions, cancellation, and durable finalization. Normal hooks are not a universal finally block.

## after_model: decide whether the next action is valid

<SourceRef file="backend/packages/harness/deerflow/agents/lead_agent/agent.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="build_middlewares" /> places Clarification at the end of the built-in chain, near safety and length termination guards. Reverse after-hook order lets safety handling suppress inappropriate calls before later accounting and control consume the response. Extension composition must respect host ordering constraints.

| Condition | Intent | Not a promise of |
| --- | --- | --- |
| Clarification | Return a question and end this execution branch | A tool waiting indefinitely for human input |
| Provider safety termination | Suppress untrusted tool calls | Retrying until provider restrictions are bypassed |
| Output-length termination | Mark the cap and prevent incomplete actions | Successful task completion |
| Delegation limit | Bound concurrent and total calls | Automatic task planning |
| Loop/token threshold | Warn, constrain continuation, or stop | Business acceptance of the report |

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/clarification_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="ClarificationMiddleware" /> turns `ask_clarification` into displayable messages and control-flow updates; non-interactive runs use different policy. <SourceRef file="backend/packages/harness/deerflow/agents/middlewares/safety_finish_reason_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> recognizes provider-specific termination forms rather than relying on one string field.

TokenBudget is configurable and relies on available usage. A completed call can cross its threshold; it is not an exact prepaid provider-billing limit.

## Receipts establish provenance, not correctness

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/tool_receipt_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="ToolReceiptMiddleware" /> stamps corresponding ToolMessages, including messages inside Commands, and overwrites any forged receipt field from the tool. Its outer placement also records denials and errors from short-circuiting policies.

Child reports can cite receipts and the lead can check their association with actual calls. **A successful file-read receipt does not prove the file is accurate, the interpretation is correct, or the research is sufficient.**

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/tool_error_handling_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="ToolErrorHandlingMiddleware" /> normalizes exceptions and result metadata for progress, acceptance, and auditing. Business errors, policy denials, and cancellation still need distinct meanings.

## Large results, artifacts, and delivery

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/tool_output_budget_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="ToolOutputBudgetMiddleware" /> persists oversized results and substitutes typed synopses with references, with bounded fallback when persistence fails. Superseded successful `write_file.content` arguments can also be elided in the model request only, retaining original state, checkpoints, and receipts.

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/artifact_capture_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="ArtifactCaptureMiddleware" /> captures on the next `before_model`, rather than wrapping every tool return in a Command. It extracts artifact references into `tool_artifacts` for later handle use.

For our report, separate these facts:

~~~text
Successful write_file: a file exists in the execution environment
Artifact metadata: the runtime records a reference
present_files: the artifact is presented for the user
Downloadability: the file exists, access is authorized, storage is reachable
~~~

Verify delivery across file creation, reference registration, presentation, and authorized download.

## after_agent and worker finalization

Normal completion may generate a title, submit memory updates, and release the execution's sandbox lease. Memory writes depend on agent configuration, memory mode, and the selected backend.

<SourceRef file="backend/packages/harness/deerflow/sandbox/middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SandboxMiddleware" /> releases this execution's resource claim. With shared child execution, one release must not destroy another execution's sandbox.

<SourceRef file="backend/packages/harness/deerflow/runtime/runs/worker.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="run_agent" /> coordinates event persistence, completion data, terminal state, cancellation cleanup, and stream closure. The final token does not establish that all persistence finished; graph termination cannot undo external side effects.

<Philosophy>
Keep proposed actions, authorized execution, observed outcomes, and accepted delivery distinct. Middleware enforces these boundaries and receipts make them inspectable. Task quality still depends on evidence and acceptance criteria.
</Philosophy>
