Comparing options may require file reads, search, delegation, and a final report write. These capabilities pass through assembly and authorization. **The tool system decides which candidates exist, which schemas are visible, and whether a particular call may execute.**

## Where candidates come from

<SourceRef file="backend/packages/harness/deerflow/tools/tools.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="get_available_tools" /> builds candidates from configuration, built-ins, and integrations. Configured tools use a `module.path:variable_name` reference. Agent `tool_groups`, vision support, host-bash policy, and live host capabilities narrow the set.

A configuration `name` labels an entry; `BaseTool.name` identifies the model schema and execution route. Deduplication uses the actual tool name, making source order relevant for collisions.

MCP and ACP supply external capabilities. Extension tools also participate in host assembly and policy; they are not exempt entry points.

## Authorization covers every tool source

The factory appends tools such as `describe_skill`, memory, and project-document access. These also pass through <SourceRef file="backend/packages/harness/deerflow/authz/tool_filter.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="apply_tool_authorization" />, preventing late additions from bypassing the initial filter.

Middleware may declare tools too, such as a task-list tool. <SourceRef file="backend/packages/harness/deerflow/agents/middlewares/tool_declarations.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="narrow_declared_tools" /> and subsequent verification include these declarations in the same permission boundary. Inspecting only `create_agent(tools=...)` is insufficient.

<SourceRef file="backend/packages/harness/deerflow/guardrails/middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="GuardrailMiddleware" /> performs execution-time checks. Assembly asks whether a tool is offered; execution asks whether this particular invocation is allowed. A denial must become an understandable result, not a claim that execution occurred.

## Skill metadata and tool authorization

`SKILL.md` stores `allowed-tools` as compatibility metadata. The field does not participate in agent tool filtering or execution authorization.

<SourceRef file="backend/packages/harness/deerflow/skills/types.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="Skill" /> stores the field. Agent configuration, authorization providers, and runtime policies determine tool permissions; skill visibility and activation use a separate resource-authorization path.

Inspect assembly results and execution policy to determine which tools a run may use. The value of `allowed-tools` does not change that scope.

## Deferred tools: registered before their schemas are exposed

With `tool_search.enabled`, <SourceRef file="backend/packages/harness/deerflow/tools/builtins/tool_search.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="assemble_deferred_tools" /> builds a catalog of MCP tools. The model gets a smaller discovery surface and promotes the schemas it needs through `tool_search`.

~~~text
Registration and authorization
  → deferred catalog + catalog_hash
  → tool_search discovery
  → promoted state update
  → schema exposed on a later model call
  → promotion and authorization checked at execution
~~~

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/deferred_tool_filter_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="DeferredToolFilterMiddleware" /> controls schema visibility and blocks unpromoted calls. Promotion is scoped by catalog hash, preventing an old promotion from automatically authorizing a changed tool with the same name.

MCP routing can also auto-promote schemas when configured. It assists discovery without bypassing authorization. Skills have an independent `skills.deferred_discovery` switch, covered at stop eight.

## Tool calls have different consequences

| Kind | Example | Effect |
| --- | --- | --- |
| Read or execute | File read, search, shell | Supplies model input and may cause external side effects |
| State update | `present_files` | Returns a Command updating artifact state for the UI |
| Control flow | `ask_clarification` | Middleware changes how the run continues |
| Delegation | `task` | Starts a child agent and returns results and associated evidence |
| Discovery | `tool_search`, `describe_skill` | Changes available information without granting higher authority |

For our prompt, the model might read first and search after discovering missing evidence, or ask which three options to compare. Input and runtime policy govern these branches, not registration order.

## MCP also owns session and file integration

<SourceRef file="backend/packages/harness/deerflow/mcp/tools.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> wraps sessions, calls, and results as well as schemas. The scope of a stdio session, its workspace and temporary files, and virtual-path mapping determine how outputs return to the current thread.

Being able to invoke a browser tool does not establish that the user can download its screenshot. Delivery also requires paths, artifact metadata, ownership, and persistence. Durable MCP tasks are likewise distinct from a tool call that simply waits forever.
