The lead can research three options itself or delegate independent investigations. **Delegation is useful when independent parallel work, specialist capabilities, or context isolation justify its coordination cost.** Children editing the same report can lose those gains to coordination and conflicts.

A subagent is another complete agent. The lead's tool node invokes `task`; that adapter starts an executor, which assembles and runs a child graph.

## The task tool adapts delegation

<SourceRef file="backend/packages/harness/deerflow/tools/builtins/task_tool.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="task_tool" /> accepts a prompt, type, description, and optional `context_mode`, model, and `acceptance_criteria`. It prepares context, admits and schedules work, observes execution, and returns a consumable result.

The normal result path uses a Command containing a ToolMessage to return the result, status, usage, and verification metadata to the lead.

<SourceRef file="backend/packages/harness/deerflow/subagents/executor.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentExecutor" /> creates the graph and owns execution, timeout, cancellation, and result collection. Provider `tool_call_id` correlates messages/UI; a server-generated `execution_id` identifies registry ownership and cancellation. Provider IDs can repeat across runs.

## Inherit context, narrow capability

| Dimension | Behavior |
| --- | --- |
| User/thread/workspace | Parent identity and shared execution environment |
| Model | Inherited or configured, subject to authorization and explicit selection |
| Tools | Narrowed by child configuration and execution policy; recursive task excluded |
| Skills | Discovery/activation limits; allowed-tools does not authorize or filter tools |
| Conversation context | Isolated and bounded snapshot modes differ |
| Checkpoint | Ordinary child graph uses `checkpointer=False` |
| Resources | Shared sandbox, separate execution lease |

<SourceRef file="backend/packages/harness/deerflow/subagents/context_snapshot.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> provides bounded context rather than copying every parent internal state or permission. Child discovery policy must not rewrite the lead-owned shared skill filesystem.

## Three different budgets

<SourceRef file="backend/packages/harness/deerflow/agents/middlewares/subagent_limit_middleware.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentLimitMiddleware" /> controls proposed delegation counts; <SourceRef file="backend/packages/harness/deerflow/subagents/capacity.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> governs process execution capacity; <SourceRef file="backend/packages/harness/deerflow/subagents/config.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentConfig" /> and <SourceRef file="backend/packages/harness/deerflow/subagents/turn_budget.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> govern execution turns and time.

- Per-round concurrency bounds the tasks admitted from one model response.
- Per-run total limits prevent repeated rounds from creating unlimited children.
- Child turn/time limits bound each admitted execution.

`max_turns` counts agent turns and is translated into super-steps for the assembled graph. Concurrency, total delegation, turns, and timeout have separate settings; follow their effective values for the run.

## Completed is not accepted

Child reports are self-reports. Results can also carry receipts and deterministic acceptance checks:

| Criterion | Establishes | Does not establish |
| --- | --- | --- |
| File exists/non-empty | Presence or content | Correctness or adequate sourcing |
| `file_written` | Matching write evidence for this execution | Business acceptance |
| `tests_passed` | Correspondence to recorded command and test output | Every test/environment passed |
| JSON/CSV checks | Supported syntax or header conditions | Full schema and business validity |
| Free-text requirement | May remain undecidable | Automatic success |

<SourceRef file="backend/packages/harness/deerflow/subagents/acceptance_checks.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> retains `UNVERIFIED` for insufficient evidence or unsupported checks. Completed execution, failed conditions, and missing evidence differ. The lead should reuse valid work and address only the remaining conditions.

The report file can exist while its comparison remains biased or unsupported. That still requires inspecting the sources.

## Durable batches are a separate path

<SourceRef file="backend/packages/harness/deerflow/tools/builtins/batch_task_tool.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" /> supplies `batch_task`, `batch_status`, `cancel_batch`, and `read_batch_result`. <SourceRef file="backend/packages/harness/deerflow/subagents/batch_service.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="SubagentBatchService" /> manages durable items, leases, execution, and recovery for bounded independent work.

Batch records and results are durable, with recovery coordinated through item state and execution evidence. Ordinary child graphs use `checkpointer=False`. Enabling the batch service requires persistent database configuration.

<Philosophy>
Delegation separates computation and evidence. A reliable parent must understand who executed what, why execution stopped, which conditions were established, and which claims still need verification.
</Philosophy>
