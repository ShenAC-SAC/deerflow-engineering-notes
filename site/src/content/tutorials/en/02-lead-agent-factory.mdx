The report request has a run identity. Its factory selects the model, tools, middleware, and state structure. **Assembly builds the graph; invocation performs reasoning.**

The factory returns `LeadAgentAssembly` with the executable graph, effective model, and an optional assembly descriptor.

## Identity precedes capability

The core resolves authoritative identity before loading the user's custom agent. Ordinary client fields cannot replace reserved host authentication fields. It then narrows:

- Agent skills against resource authorization.
- Allowed child types, concurrency, and total delegation.
- Interactive clarification and host-provided scheduling capabilities.
- Model access and tool permissions.

For example, `allowed_subagents=[]` forbids delegation even if the request enables subagents. A live scheduler capability cannot be forged through checkpoint configuration.

## Model selection includes normalization

Normal resolution considers request, agent defaults, global configuration, and authorization. Explicit selection must be consistent and allowed rather than silently replaced.

Options such as `thinking_enabled` distinguish omission from explicit `false`. <SourceRef file="backend/packages/harness/deerflow/models/reasoning.py" sha="51d59a1cdff92626bd9f03f1b2254f34a824ca3e" symbol="resolve_reasoning_request" /> normalizes the result against the model contract: unsupported thinking is disabled, required thinking is enabled, and effort values may map to provider vocabulary.

Requested and effective settings can differ. Metadata and `effective_model` must represent actual execution.

<MarginNote>In-graph model construction uses `attach_tracing=False` because callbacks attach at the graph invocation root. Double attachment can duplicate spans and break user/session attribution.</MarginNote>

## Assembly steps

The normal branch:

1. Collect candidates and append available skill-discovery, memory, project-document, and task-continuity tools.
2. Authorize tools, then construct the deferred MCP catalog.
3. Compose middleware and extensions; narrow and verify middleware-declared tools.
4. Render the prompt from the same effective capabilities.
5. Select a checkpoint-compatible state schema and call `create_agent()`.
6. Return `LeadAgentAssembly`.

Bootstrap is a narrow branch for creating custom agents. Some webhook origins withhold self-modification tools so external comments cannot persist changes to an agent.

## What the descriptor records

`LeadAgentAssembly` has three core fields:

| Field | Meaning |
| --- | --- |
| `graph` | Executable graph |
| `effective_model` | Selected model |
| `descriptor` | On-demand assembly description; may be None when no relevant evidence consumer needs it |

The descriptor records the model, tools, middleware, and effective policies for extensions and auditing. It describes execution configuration; it does not validate task results or replace the executable graph.

<Philosophy>
Returning the graph with its assembly description puts execution and the basis for explaining execution at one boundary. Compatibility hosts take the graph; evidence-aware hosts retain the description.
</Philosophy>
